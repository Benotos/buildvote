Roadmap

What ships, in order. Foundations, launch and the voting backend are done, and the agent is building in public. Dates are added as they are locked in.

  1. Step 1Done

    Foundations

    This site, the whitepaper, the fee rules and the agent's working setup: a public repo, hard usage limits and full logging. The agent is already building in public.

    Done when: the site is live, the whitepaper is public and the agent can run end to end on a test task.

  2. Step 2Done

    Launch

    The token is live. Supply, holders and the fee split are public and linked from this site.

    Done when: the token exists and the final parameters are posted and linked from this site.

  3. Step 3Done

    Voting backend

    Balance checks, signed message checks and a public tally that anyone can recompute from the raw signatures.

    Done when: a test round runs with real signatures and the tally can be reproduced by someone outside the team.

  4. Step 4In progress

    Live dashboard

    One page for commits, API spend and creator fee claims, each linked to its source record.

    Done when: every number on the dashboard links to a commit, an invoice log or a transaction.

  5. Step 5Up next

    Round 1

    The first real ballot. Holders vote, the agent builds the winner in public and ships it.

    Done when: the winning tool is live and its build log and costs are public.

  6. Step 6Planned

    Ongoing rounds

    Regular rounds, with the rules adjusted in public as we learn what works.

    Done when: this never finishes by design. Each round gets its own write up.

An empty box means planned. A step gets its X only when the work ships and you can check it.

Build.vote is an experimental project. Tokens are volatile and you can lose everything you put in. Nothing here is financial, investment or tax advice, and no return is promised.
